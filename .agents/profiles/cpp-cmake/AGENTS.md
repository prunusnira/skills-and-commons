# AGENTS.md

이 문서는 CMake 기반 C++ 프로젝트에서 코드를 분석·수정·작성할 때 참고하는 지침 템플릿이다. 실제 프로젝트의 `AGENTS.md`, 빌드 설정, 코드 관례가 다르면 해당 프로젝트의 규칙을 우선한다.

## 작업 디렉터리

- 별도 Git worktree를 만들거나 다른 worktree로 전환하지 않는다.
- 사용자가 열어 둔 작업 디렉터리에서 작업하고, 기존 로컬 변경사항을 유지한다.
- 요청과 무관한 파일을 수정하거나 되돌리지 않는다.

## 1. 작업 전 확인

- 최상위 및 관련 하위 `CMakeLists.txt`, `cmake_minimum_required`, 대상 간 의존성, 기존 빌드 명령을 확인한다.
- `CMakePresets.json`, toolchain 파일, 의존성 관리 방식이 있는지 확인한다. 설정 파일이나 패키지가 있다고 추측하지 않는다.
- 프로젝트의 C++ 표준, 컴파일러와 지원 플랫폼, 예외·RTTI 설정, 포매터·정적 분석·테스트 구성을 확인한다.
- 변경할 공개 API와 호출부, 주변 코드의 소유권·오류 처리 방식을 읽는다. 파일이나 대상 이름은 검색해 확인한다.

## 2. CMake 구성

- 기존 preset, generator, toolchain, 빌드 디렉터리와 대상 구조를 따른다. 요청 없이 C++ 표준이나 빌드 시스템을 일괄 변경하지 않는다.
- 실행 파일과 라이브러리의 의존성은 가능하면 CMake 대상 사이에 표현한다. include 경로, 컴파일 정의·옵션, 링크 의존성은 사용 범위에 맞게 대상에 설정한다.
- `PUBLIC`, `PRIVATE`, `INTERFACE`는 소비자에게 전달할 요구사항인지 확인해 선택한다. 공개 사용 요구사항을 바꾸면 해당 대상을 사용하는 코드도 확인한다.
- `find_package`, FetchContent, 서브모듈, 패키지 관리자 중 프로젝트가 이미 쓰는 방식을 우선한다. 요청 없이 같은 의존성을 다른 방식으로 중복 도입하지 않는다.
- 생성된 빌드 디렉터리, `CMakeCache.txt`, `CMakeFiles/`를 소스처럼 수정하거나 커밋하지 않는다. `CMakeUserPresets.json`은 개인 설정으로 취급한다.

## 3. C++ 코드

- 프로젝트가 실제로 사용하는 C++ 표준과 코드 스타일을 따른다. 새 언어 기능을 쓰기 위해 표준 버전을 올리지 않는다.
- 자원 소유권과 수명을 명확히 하고 RAII 및 기존 자원 관리 타입을 우선 사용한다. 수동 할당·해제를 새로 도입할 때는 필요한 이유를 확인한다.
- 오류 코드는 오류 코드로, 예외는 예외로 다루는 기존 계약을 유지한다. 실패를 조용히 무시하거나 기존 호출부가 예상하는 오류 형태를 바꾸지 않는다.
- 인덱스 범위, null, 댕글링 참조, 정수 변환, 동시 접근처럼 변경과 관련된 미정의 동작 가능성을 확인한다.
- 공개 헤더·함수 시그니처·바이너리 인터페이스를 바꾸면 사용처와 호환성 영향을 확인한다. 플랫폼별 코드에서는 대상 플랫폼의 경로·컴파일러 차이를 고려한다.
- 짧은 변경을 위해 새 추상화나 대규모 리팩터링을 만들지 않는다. 주석은 코드만으로 알기 어려운 이유를 설명할 때만 쓴다.

## 4. 테스트와 검증

- 기존 테스트 프레임워크와 CTest 등록 방식을 우선한다. 사용할 수 있다면 `cpp-cmake-tests` skill의 테스트 설계 및 CMake 통합 지침을 참고한다.
- 공개 동작과 계약상 중요한 오류·경계값을 검증한다. 테스트 전용으로 제품 API를 불필요하게 노출하거나 구현 파일을 직접 포함하지 않는다.
- 프로젝트 명령으로 configure와 변경 대상 빌드를 확인한 다음 관련 테스트를 실행한다. CTest를 사용한다면 테스트가 실제로 등록되고 실행됐는지 확인한다.
- 다중 구성 생성기는 빌드와 테스트에 같은 구성을 지정한다. 크로스 컴파일 등으로 실행할 수 없다면 빌드 검증과 실행 검증을 구분해 보고한다.
- 포매터·정적 분석·전체 테스트가 프로젝트에 설정되어 있다면 변경 범위와 비용에 맞춰 실행한다. 실행하지 못한 검증을 통과했다고 말하지 않는다.

## 5. Git과 보고

- 커밋과 푸시는 사용자가 요청한 경우에만 수행한다. 기존 변경사항과 요청 범위를 구분한다.
- 결과에는 변경 내용, 실행한 configure·build·test 명령과 결과, 확인하지 못한 범위를 간결히 적는다.
