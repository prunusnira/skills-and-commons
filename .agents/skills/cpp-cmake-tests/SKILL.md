# C++ CMake 테스트 작성

## 시작 전에 확인할 것

- 대상 프로젝트의 `AGENTS.md`, 테스트 대상의 공개 계약, 주변 테스트, C++ 표준과 컴파일 옵션을 확인한다.
- `CMakeLists.txt`, `CMakePresets.json`, 테스트 의존성, 기존 빌드·CTest 명령을 확인한다. GoogleTest, Catch2 또는 자체 테스트 실행기가 이미 있다면 그대로 사용한다.
- 새 프레임워크나 테스트 전용 공개 API를 먼저 도입하지 않는다. 필요한 테스트 수준과 기존 빌드 구조를 보고 가장 작은 변경을 선택한다.

## 테스트 작성 기준

- 구현 단계보다 공개 입력과 관찰 가능한 결과를 검증한다. 테스트 이름에는 조건과 기대 동작을 담는다.
- Given, When, Then 흐름이 읽히게 작성한다. 주석은 단계가 불분명할 때만 붙인다.
- 정상 동작과 함께 계약상 중요한 오류·경계값을 검증한다. 의미 없는 생성 확인이나 단순 실행 확인으로 테스트 수를 채우지 않는다.
- 외부 경계만 필요한 만큼 fake 또는 mock으로 대체한다. 테스트별 상태와 자원은 격리하고 RAII로 정리한다.
- 기존 프레임워크의 assertion을 사용한다. 자체 실행기라면 실패 시 진단과 0이 아닌 종료 코드를 반환한다. 릴리스 빌드에서 제거될 수 있는 C/C++ `assert`에 검증을 맡기지 않는다.

구체적인 사례 선택, assertion, fixture, 비결정성 처리에는 [테스트 설계](references/test-design.md)를 읽는다. CMake 대상 등록과 실행이 필요하면 [CMake·CTest 통합](references/cmake-ctest.md)을 읽는다.

## 완료 확인

- 변경한 테스트 대상을 빌드하고 프로젝트의 테스트 실행기로 실행한다. CTest를 사용한다면 등록 목록에 기대한 테스트가 있는지도 확인한다. 실패 또는 실행 불가 원인을 숨기지 않는다.
- 답변에는 검증한 동작, 실행 명령과 결과, 실행하지 못한 범위를 간결히 적는다.
